# Subagents: a primer

A **subagent** is a specialized assistant Claude Code spawns to handle a focused task in its
**own context window**, then report just the result back. Use them for parallel work, for keeping
the main thread clean, and for routing a job to a tool-restricted specialist. A subagent is a
markdown file with YAML frontmatter (the frontmatter configures it, the body is its system prompt).

## 1. Project subagents in this folder

| Agent | Tools | What it teaches |
| --- | --- | --- |
| `design-reviewer` | Read, Grep, Glob | A read-only reviewer: the allowlist makes "never edits" a fact. |
| `copy-polish` | Read, Edit, Grep, Glob | A narrow editor that only touches user-facing strings. |
| `setup-auditor` | Read, Grep, Glob, WebFetch, WebSearch | Checks this repo against the live docs. |
| `security-reviewer` | Read, Grep, Glob | Read-only security review. Preloads the `security-checklist` skill. Deliberately has **no memory** (memory would add Write and Edit). |
| `test-writer` | Read, Grep, Glob, Edit, Write, Bash | Writes and runs tests. Preloads `write-tests`. Must show a bug test failing before any fix. |
| `code-reviewer` | Read, Grep, Glob, Bash (+ Read, Write, Edit from memory) | Reviews the diff against the team checklist and learns recurring findings. Has `memory: project`. The contrast with `security-reviewer`: memory buys learning and costs the read-only guarantee. |
| `qa-explorer` | Read, Grep, Glob, `mcp__playwright` | Exploratory QA in a real browser through the Playwright MCP. Has `memory: project`. |
| `playwright-test-planner` / `-generator` / `-healer` | Playwright test MCP tools | Generated by `npx playwright init-agents --loop=claude` (see below). |

## 2. Frontmatter fields used here

- `name`, `description`: required. The description is how Claude decides when to delegate.
- `tools`: allowlist. Omit it and the agent inherits everything. `mcp__<server>` grants every tool
  from one MCP server.
- `model`: `sonnet`, `opus`, `haiku`, a full model id, or `inherit` (use the session's model).
- `skills`: preload whole skills into the agent's context at startup.
- `mcpServers`: MCP servers the agent can use, by name (from `.mcp.json`) or defined inline.
  Inline servers stay out of the main conversation's context entirely.
- `memory`: `project`, `local` or `user`. A persistent notebook (see below).
- Also worth knowing: `permissionMode` (for example `plan`), `isolation: worktree` (run in a
  throwaway git worktree), `maxTurns`, `effort`, `color`, `background`.

## 3. Agent memory: the one built-in Claude memory that lives in the repo

`memory: project` gives an agent a folder at `.claude/agent-memory/<agent-name>/`. The first 200
lines (or 25 KB) of its `MEMORY.md` load into the agent every time it runs, and the agent edits it
as it learns. Because that folder is inside the repo, it gets committed, so the whole team's agent
learns together. Compare:

- **Auto memory**: Claude's own notes, in `~/.claude/projects/<repo>/memory/` on your machine. Never shared.
- **CLAUDE.md, rules, `memory/`**: shared through git, but plain files that people mostly write.
- **Agent memory, `project` scope**: managed by Claude Code, written by the agent, stored in the
  repo. Of the built-in memory systems, it is the only one that travels through git.
- `local` scope uses `.claude/agent-memory-local/` (gitignored); `user` scope lives in `~/.claude/agent-memory/`.
- Agent memory is part of auto memory: turn auto memory off and the `memory` field does nothing.

See `.claude/agent-memory/code-reviewer/MEMORY.md` (nearly empty, so the first review's notes show up as a diff) and `.claude/agent-memory/qa-explorer/MEMORY.md` (seeded with selectors).

## 4. Built-in and plugin agents

Always available, no file needed:
- **Explore**: read-only, fast search across many files. Returns conclusions, not file dumps.
- **Plan**: designs an implementation strategy without writing code.
- **general-purpose**: catch-all for multi-step research.

Installed plugins can add more (this repo enables `example-skills`).

## 5. Playwright's test agents

`npx playwright init-agents --loop=claude` writes three agents into `.claude/agents/`, a
`specs/README.md`, and a `playwright-test` MCP server entry. They work as a loop:

1. **planner** explores the running app and writes a Markdown test plan into `specs/`.
2. **generator** turns each plan scenario into a Playwright test by performing it live.
3. **healer** runs failing tests, debugs them in the browser, and repairs the test.

They are committed here unchanged. ⚠️ `init-agents` **overwrites `.mcp.json`** with only its own
server. Run it in a scratch worktree, or re-merge `.mcp.json` by hand afterwards.

Do not copy their `tools` lists as a model for your own agents. They name `LS` and `MultiEdit`,
which are not current Claude Code tools, so Claude Code silently drops them. The other entries
(Glob, Grep, Read, Edit, Write and the `mcp__playwright-test__*` tools) do the real work. The
agents in section 1 show the current tool names.

## 6. How you invoke them

- **Automatically**: Claude delegates when a task matches an agent's `description`, and can run
  several in parallel ("review each API route in parallel").
- **By name**: "use the security-reviewer agent on app/src/app/api".
- **Creating one**: ask Claude ("create a project agent that...") or write the file yourself.
  Since v2.1.198, `/agents` no longer opens a wizard: it prints a reminder to do exactly that.

---

**The mental model:** a subagent does a focused job in its own context and reports a summary back
to you. When agents need to talk to *each other*, that is **agent teams** (experimental, behind
`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, terminal CLI only, not Desktop; and while it is on, a
subagent Claude names launches as a teammate instead, which is why this repo does not turn it on).
When a script should orchestrate dozens of agents, that is a **workflow** (`.claude/workflows/`).
