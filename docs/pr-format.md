# Pull request descriptions

Every PR description uses these five headings, in this order:

1. **Summary**: one or two sentences on what changed and why.
2. **What Claude did**: the parts Claude wrote or changed.
3. **What I verified**: what a person read, ran or checked by hand.
4. **How it was tested**: the commands run (`npm run check`, `npm run test:e2e`) and new tests added.
5. **Risk**: anything a reviewer should look at harder, or "Low" with a reason.

Plain words, short sentences, no hype words, no em-dashes.
